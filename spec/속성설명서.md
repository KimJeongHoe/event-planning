# 행사·상시 서비스 사례 DB — 속성 설명서 (v1, 2026-11-02)

파일: `사례DB.csv`(UTF-8, BOM 포함), `FAQ.csv`(UTF-8, BOM 포함). 여러 값은 `|`로 구분. 출처 여러 개는 ` | `로 구분.
수집 원칙: 출처에 없는 결과·수치는 쓰지 않음(빈칸). 원문 문장·사진을 옮기지 않고 요약. 개인 이름·얼굴·연락처 금지. 가게 이름은 공개 기사·공식 자료에 나온 경우만.

| 합친사례번호 | merged_from | 이 사례에 합쳐진 중복 사례 번호(합쳐진 사례는 merged/합쳐진사례.csv에 보존) |
| 수집파일 / 수집ID | src_file / orig_id | 병합 추적용 |

## 4. 실제/응용 구분 규칙
- 실제: 출처에서 실제로 한 행사·서비스·가격 구조. 출처 URL 필수.
- 응용: 실제 사례를 다른 업종·상황·시점에 맞게 바꾼 안. `kind=응용`, `base_ids`에 바탕 실제 사례 번호 필수. 응용 사례에는 `known_result`를 쓰지 않음(출처 없음).
- 같은 사례가 여러 출처에 나오면 한 건으로 묶고 출처를 모두 적음.
