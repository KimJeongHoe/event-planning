# 수집 지침 (연구 에이전트용)

## 도구·네트워크 (중요)
- WebSearch(standard 우선, 결과가 얇으면 extended)가 주 채널. 검색 결과 요약과 URL을 근거로 사례를 기록한다.
- WebFetch는 다음 호스트만 열린다: law.go.kr, ftc.go.kr, kca.go.kr, nts.go.kr, mfds.go.kr. 그 밖의 호스트(뉴스·블로그·배민·토스·브런치 등)는 네트워크 정책으로 막혀 있으니 시도하지 말고 검색 결과만 쓴다.
- 검색 결과에 실제로 나온 URL만 적는다. URL을 지어내지 않는다. 날짜를 모르면 빈칸.
- 로그인 필요한 곳·대량 수집·차단 우회 금지. 공개된 페이지의 검색 결과 요약만 쓴다.

## 사례 품질
- 실제로 한 행사·서비스·가격 구조만 `실제`. 기사·공지·노하우 글에 "했다/하고 있다"로 나온 것. 일반론 가이드("이렇게 하면 좋다")는 출처에 구체 실행 사례가 없으면 넣지 않는다.
- 결과 수치(매출·손님 수)는 출처에 있을 때만. 추정 금지.
- 원문 문장을 옮기지 않고 요약. 개인 이름·얼굴·연락처 금지. 가게 이름은 공개 기사·공식 자료에 나온 경우만.
- 위험한 사례(처분·논란)도 뺴지 않고 경고·질문과 답·변형안을 붙인다.
- 평가 칸(체감가치·차별성·입소문·난이도)은 정수 1~5로 직접 평가.
- 각 사례에 `faq_ids`(F001~F050 중 해당) 또는 `case_qna`(사례 특화 질문·답) 중 하나 이상. 위험·애매한 사례는 둘 다.
- `variants`는 2개 이상(①②③). 위험이 있으면 위험 줄인 안 포함.

## 출력

- `/home/user/event_db/raw/<접두어>_log.md` 에 검색어 목록, 막힌 원천, 비어 있는 조합, 메모.
