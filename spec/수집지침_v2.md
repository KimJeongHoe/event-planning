## 바뀐 핵심 원칙
1. **원문을 직접 열어 확인한 것만 `kind="실제"`.** WebSearch는 원문 URL을 찾는 데만 쓰고, 반드시 `python3 -I scripts/fetchtext.py "<URL>" 5000` 으로 본문을 열어 사례 내용(누가·무엇을·조건·혜택·기간·결과)을 본문에서 확인한다. 검색 요약만 있고 본문을 못 연 것은 넣지 않는다(로그에 "본문 못 엶"으로 적기).
2. 각 실제 사례에 `verify_status:"확인함"`, `verify_note:"열람 2026-11-02: <URL> 본문에서 <확인한 핵심 사실 요약>"`.
3. 막힌 사이트는 우회하지 않는다(프록시·캐시·미러·아카이브 금지). 응답 코드와 함께 로그에 적는다. 이미 알려진 막힌 곳: ftc.go.kr, nts.go.kr, mfds.go.kr, ppc.go.kr, kipo.go.kr, donga.com, ce.baemin.com, web.archive.org, mk.co.kr, kukinews.com, i-boss.co.kr, qsrmagazine.com, squareup.com, ops.textmarketer.co.uk. 본문이 자바스크립트로만 나와 비어 있는 페이지도 "본문 못 엶".
4. 법 근거는 `law_src/*.txt`(법령 원문)에서 확인한 조항만. 조문 보기 `python3 -I scripts/art.py "<법령명 일부>" <조>`; 없는 법령은 `python3 -I scripts/lawfetch.py law_src 법령|행정규칙 "<정확한 이름>"`. 확실치 않으면 "확인 필요".
5. 결과 수치는 본문에 있을 때만. 원문 문장 통째 복사 금지(요약). 개인 이름·연락처 금지(가게·브랜드 이름은 기사·공식 자료에 나온 경우만). 손님·직원 이름은 쓰지 않는다.
6. 위험 사례도 빼지 않는다: 경고 4칸 + case_qna(Q/진행여부/근거/조건/대안 ①② /확인할 곳) + variants(위험 줄인 안 포함).
7. 응용 사례를 만들 경우 `kind="응용"`, 이름 앞 "[응용] ", base_ids에 바탕 실제 사례 번호(병합 정수 번호 또는 이번에 넣은 수집ID), known_result 빈칸, verify_status 빈칸.

## 저장
- `raw/<접두어>.jsonl` (한 줄 JSON, 키는 에이전트_공통브리프.md 키 + verify_status, verify_note). id는 "<접두어>-001"부터. 10건마다 append 저장, 끝에 json.loads 검증.
- `raw/<접두어>_log.md`: 검색어, 열어 본 URL과 응답 코드, 막힌 곳, 본문 못 연 후보, 비어 있는 조합, 다음에 찾을 곳.
- 기존 DB와 겹치는 사례는 넣지 않는다: `python3 -I -c "import json;[print(json.loads(l)['id'],json.loads(l)['name']) for l in open('merged/사례DB.jsonl',encoding='utf-8')]" | grep <키워드>` 로 먼저 확인.
- 개인정보가 있는 페이지(후기 작성자 이름 등)는 그 정보를 옮기지 않는다.
