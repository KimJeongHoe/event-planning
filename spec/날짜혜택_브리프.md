# 출처날짜·혜택 보강 브리프 (회차 7)
입력 qna_packets/dates_benefit.jsonl(실제 사례 중 출처날짜 또는 혜택이 빈 것) → 출력 qna_results/dates_benefit.jsonl. 빈 칸만.
- source_dates: 출처 주소 순서대로 기사·글 날짜(YYYY-MM-DD 또는 YYYY-MM). 원문 본문에서 확인: reports/출처제목_스냅샷.tsv(본문 첫 날짜 후보), src_cache/<md5앞12자>.txt, /tmp/claude-0/-home-user/9b7137bb-80cc-5ef4-adb4-73711cbdc18f/scratchpad/cur/<md5앞12자>.txt, 없으면 `python3 -I scripts/fetchtext.py "<URL>" 4000`. 스냅샷 날짜는 후보일 뿐이니 본문에서 '입력/게재/작성' 날짜인지 확인(관련기사 날짜 금지). 못 찾으면 그 자리 '날짜 미상', 여러 출처는 ' | '로.
- benefit: 원문에 있는 혜택만 요약. 혜택이 없는 사례(처분·논란·정책)는 `해당없음(이유)`, 원문에 없으면 `원문에 혜택 언급 없음`.
- 출력 한 줄: {"case":"<orig_id>","edits":[{"field":"source_dates","after":"…"},{"field":"benefit","after":"…"}],"flag":""}. 사실 오류는 flag. 웹 검색 쓰지 않음, 막힌 곳 우회 금지. 10건마다 저장, json.loads 검증.
최종 보고: 날짜 채운 수(확인/미상), 혜택 채운 수, flag.
