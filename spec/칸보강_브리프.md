# 칸 보강 브리프 (회차 5): 측정지표·추가주문경로·수량·1인한도

입력: `field_packets/field_N.jsonl` — kpi(측정지표), upsell_path(추가주문경로), limit(수량·1인한도) 중 빈 칸이 있는 사례. 출력: `field_results/field_N.jsonl`. **빈 칸만 채운다**(채워진 칸은 그대로).

## 칸별 규칙
- kpi(측정지표): 이 사례의 목표(goals)에 맞는 지표 2~3개 + 재는 방법. 예: "쿠폰 회수율(POS 할인코드 '수능'으로 집계) · 행사 기간 학생 손님 수(학생증 확인 체크표) · 재방문율(2주 내 도장 재사용)". 뭉뚱그린 말("매출 증가") 금지.
- upsell_path(추가주문경로): 혜택에서 추가 지출로 이어지는 구체적인 길 "A → B". 예: "무료 공깃밥 → 찌개 추가 주문", "커트 할인 → 클리닉·홈케어 제품". 추가 주문으로 이어지지 않는 성격(사회공헌·법 처분·정책 논란 등)이면 `없음(이유)`.
- limit(수량·1인한도):
  - **실제 사례**: 원문에 있는 것만. 출처 본문을 확인한다 — `src_cache/<md5앞12자>.txt`(`python3 -I -c "import hashlib,sys;print(hashlib.md5(sys.argv[1].encode()).hexdigest()[:12])" "<URL>"`) 또는 `python3 -I scripts/fetchtext.py "<URL>" 6000`. 원문에 수량·1인 한도·선착순·1테이블 1회 등이 있으면 그대로 요약해 적고, 없으면 `원문에 한도 언급 없음`. 지어내지 않는다. 막힌 사이트 우회 금지.
  - **응용 사례**: 위험·원가를 고려해 설계한 한도를 `제안: …` 형식으로(예: "제안: 1테이블 1회, 하루 선착순 30명").
  - 한도가 성격상 없는 경우(가격 구조·상시 정책·처분 사례 등): `해당없음(이유)`.
- 사례의 사실 칸(name·summary·condition·benefit·known_result·출처)은 고치지 않는다. 원문 확인 중 사실 오류를 발견하면 notes 수정 대신 출력 줄에 "flag":"…"로 남긴다.

## 출력 (한 줄에 사례 1건, 입력과 같은 순서·줄 수)
{"case":"<orig_id>","edits":[{"field":"kpi","after":"…"},{"field":"upsell_path","after":"…"},{"field":"limit","after":"원문에 한도 언급 없음"}],"flag":""}
10건마다 append 저장, 끝에 줄 수·json.loads 검증. 웹 검색 쓰지 않음.
## 최종 보고(짧게)
칸별 채운 수, limit 중 원문에서 찾은 수 / 원문에 한도 언급 없음 / 제안 / 해당없음 수, flag 목록.
