# 연출 칸 보강 브리프 (회차 6)

입력 `staging_packets/st_N.jsonl`(연출 칸이 빈 사례) → 출력 `staging_results/st_N.jsonl`. 빈 연출(staging) 칸만 채운다.
- 연출 = 현장 분위기·보여 주는 장치(현수막·포토존·소품·유니폼·음악·시식대·게시물 디자인·영상·손편지·이벤트 진행 방식 등).
- **실제 사례**: 원문에 있는 연출만 요약. 출처 본문 확인: `src_cache/<md5앞12자>.txt`(`python3 -I -c "import hashlib,sys;print(hashlib.md5(sys.argv[1].encode()).hexdigest()[:12])" "<URL>"`) 또는 `python3 -I scripts/fetchtext.py "<URL>" 8000`. 원문에 연출이 없으면 `원문에 연출 언급 없음`, 원문을 못 열면 `원문 확인 불가(이유)`. 지어내지 않는다. 막힌 곳 우회 금지.
- **응용 사례**: `제안: …` 형식으로 사례에 맞는 연출 1~2문장(원가·위험 고려).
- 성격상 연출이 없는 사례(처분·법령·가격 정책·온라인만): `해당없음(이유)`.
- 원문 확인 중 사실 오류를 보면 "flag"에 적는다(사실 칸은 고치지 않음).
- 출력 한 줄: {"case":"<orig_id>","edits":[{"field":"staging","after":"…"}],"flag":""}. 입력과 같은 순서·줄 수, 10건마다 저장, 끝에 json.loads 검증. 웹 검색 쓰지 않음.
최종 보고: 원문에서 찾음 / 원문에 연출 언급 없음 / 원문 확인 불가 / 제안 / 해당없음 수, flag 목록.
